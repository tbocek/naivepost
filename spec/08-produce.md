# 08 — Produce

Renders the video, writes the subtitles in each language, and writes the title, description and thumbnail. The words half and the render half run side by side; neither reads the other's files.

- **Encoder settings** (labels, options, defaults and tooltips in `inventory/produce.md` §A, normative): Container mp4/mkv/webm; Codec h264/h265/vp9; Preset ultrafast…veryslow (default veryslow — REVIEW: `medium` or `slow` is a better default for hour-long sessions); Resolution 720p/1080p/original (names the short side; the cut's aspect sets the shape); Frame rate source/60/30/24; Audio 128/192/256/320 kbit/s; Subtitles burned in / track in file / none in the video (an .srt and .vtt are written beside the video either way); Translate (ticks per language in the settings list; the session's own language is never offered); Game audio 0..1 (hidden when narration is off); Quality CRF 14..34 (mark at 24); Frame timing "peak rate (VFR)"; Channels "mono"; Frame edges "blurred" (on). webm forces vp9 and turns "track in file" into "none". Output = `produce/final.<container>`, not a question. ↻ Transcode ("Encode the video again from the cut and these settings — no model call…"); ⤓ Save video (a copy elsewhere).
- **Images row**: up to 8; the first is the base the image model edits, the others references it can name ("the ship from the second image"); the base wears a crop box when its shape differs from the video's; per slot: Make base, Set Thumbnail (take this picture as it is, no model), Change…, remove; empty state "No image — the thumbnail will be drawn from the instruction alone." **Edit instruction** and **Negative prompt** boxes; **Thumbnail** with ⤓ export (JPEG under 2 MB) and ↻ redraw; the picture is a text-overlay editor: drag a box to add words printed to fill it, drag borders/middle to resize/move, ✎ to reword or remove; the title band is a box of its own.
- **Title** entry (also printed across the thumbnail the first time; after that the two are separate) with ↻ suggest (a fresh title, instruction and description; the only thing that rewrites text); **YouTube description** box.
- Inputs: "N clip(s) · mm:ss[ · no narration | · N to speak][ · no upload text]"; the tooltip explains what will be spoken first, which recordings are mixed, the voice, and whether `publish.json` exists. Outputs: "produce/ — the finished video, the per-clip encodes, the thumbnail and the upload text".

## 2. Flows

### F5.1 ▶ Produce
S1 Refuse when busy; no cut → "no cut yet — build one on the Cut step first". S2 If the render is up to date (F5.3 stamp) the encode is skipped (">>> the video is already what this page describes — not encoding it again (↻ beside Transcode encodes anyway)"); otherwise, if the video exists, confirm "Overwrite <base>?" ("<path> — size, age\n\nThe encode takes minutes and there is no undo for it."). S3 Snapshot everything on the GUI thread (cut, lines, settings, sources, publish state, aspect); the cut is the Cut page's own when it holds one (an unsaved tweak still renders), else `cut/cut.json` — one function answers "what is the cut" for the render, the subtitles, the brief and the stamp alike. S4 startRun; two halves in parallel: **words** (F5.6, its own progress line; a failure is logged "!!! the upload text and thumbnail failed: … -- the render carries on") and **render** (F5.2). S5 After both: write the `<video>` tag page (F5.5). S6 The render's error is the run's verdict; done → "produced <file> — X s, size".

```
 ▶ ──┬── words: brief ─► LLM (tools) ─► frames row ─► publish.json ─► [draw sd.cpp] ─► print words ─► thumbnail.png
     └── render: speak missing ─► plan clips ─► subtitles ─► encode clips ─► join ─► translate ─► loudness+mux ─► sidecars
                                                                                                        └─► <video> tag
```

### F5.2 The render
S1 Clear `produce/clips/`. S2 Speak every line that has no wav (job "speaking" 1/2) — unless the voice is "captions only", in which case nothing is spoken and every line is carried by the subtitle track alone (with Subtitles "none in the video" the run warns ">>> captions only and nothing in the video — the lines are in the .srt beside it"). S3 Plan one clip per cut segment (after speed effects split them): footage (rate, clamped to the recording), copies (`copy:<s>`), inserts (missing file → "clip N: <file> is not there any more — skipped"), sounds over footage; clips shorter than P.policy.minClipSeconds (0.5) are dropped with a log line naming any narration lost with them. Narration lines matched to clips (overlap ≥ half the shorter span) and fitted (F4.3). Sound plan for own-clock runs; lane mixes per clip (overlaps ≥ 0.1 s; a per-lane report "<lane> is mixed into N of the M clips"); frame box for every clip; camera paths; text, gain, hush and still cues. S4 Subtitles on the produced clock (F5.4) → `clips/final.srt`; stale sidecars beside the video deleted by exact name. S5 Encode each clip (job "clip": stems `c000_<stamp>`; -ss before -i; the filter graph of `06-effects.md` §4 plus burned subtitles; audio: speed → hush → lane bed → gains → seam dips → narration mix at P.policy.gameVolume → limiter −1 dBFS → 48 kHz format; codec args by codec/preset/CRF; every command logged). A size mismatch against clip 0 is logged (the join is a stream copy). S6 Join by stream copy ("joining"). S7 Translate the cues into the ticked languages (F5.4; after the encodes so the encoder never idles behind the LLM gate). S8 Loudness + mux: `aresample=async=1:first_pts=0,loudnorm=I=-14:TP=-1.5:LRA=11`, 48 kHz, the audio codec, subtitle tracks when "track in file" (mov_text in mp4, srt in mkv; never webm), mp4 faststart flags. S9 Sidecars `<stem>[.code].srt` and `.vtt` per language; log each. S10 Write the stamp (F5.3). Checkpoints between every subprocess.

### F5.3 What "up to date" means
The stamp = a hash of the encoder settings (without the output path), the segments, the lines (bounds, text, wav size and mtime), the sources (path, size, mtime), the aspect, the voice and the narration flag, kept as `<stem>.stamp` beside the video. Title, description, thumbnail and the upload record are not in it. The upload text is "written" when `produce/publish/publish.json` exists; deleting `publish/` starts the text over.

### F5.4 Subtitles
S1 Cues per clip: the narration lines where a clip has them, else the clip's own speech from the aligned words (narrator mic excluded), respelled from the fixed transcript; per word: a new cue at a gap ≥ P.policy.subtitleBreakSeconds (0.6), over 2 × P.policy.subtitleRowChars (42) characters, or ≥ P.policy.subtitleMaxSeconds (6); an empty cue extends the previous one. S2 On the produced clock: no overlaps; gaps under 1.2 s held; cues under 0.8 s folded into the next; wrapped at 42 chars into ≤ 2 rows; placement tags `{\an8}`/`{\an5}` for top/centre. S3 Translation per ticked language: batches of P.policy.translateBatch lines (REVIEW: new; prototype sent all lines at once and repaired gaps), numbered; message "TRANSLATE THESE N LINES INTO X. Answer with N lines, numbered as they are here:"; thinking off; **Tools**: `translate_line(n, text)`, `finish` (`02-services.md` §3.10); missing numbers re-asked once with their original numbers; still missing keep the original text with a warning; cached only when complete. The session's own language is track 0 and never translated.

### F5.5 The `<video>` tag
Poster `<stem>.jpg` (JPEG 90) from the thumbnail; tracks = the `.vtt` files on disk, the video's own language first and default; `<stem>.html` holding a bare `<video poster controls src preload="none">` with one `<track>` per language. Notes logged when the container or codec is not web-playable and that subtitles need http, not file://.

### F5.6 Upload text and thumbnail
S1 Brief: "THE FINISHED VIDEO: N clips, m:ss long." + per clip "CLIP n (at m:ss in the video, X s): session a–b" with what was seen and said, + the narration at its time in the video (or "(no narration has been written for this video)"). REVIEW: for long sessions the brief MUST be bounded (P.llm.briefMaxChars, default ~120 kB) by folding each clip to its first lines and events, and the model MAY read more with `get_lines`. S2 System = the "youtube" prompt; thinking on; web tools offered. **Tools**: `set_title`, `set_description`, `pick_frame(clip, offset)`, `set_thumbnail_instruction(text, negative?)`, `finish` (`02-services.md` §3.9). Prototype: "TITLE: …", "THUMBNAIL: <instruction | frame: clip n +s>", then the description, peeled from prose. S3 A picked frame: the nearest extracted frame, cropped to the video's shape, becomes the thumbnail as it is (no model, no GPU); the row holds that frame only; `own` = true. S4 First run with no images and no chosen frame: 3 frames evenly spread over the kept footage fill the row. S5 Write `publish.json` and `description.txt` before drawing (a failed draw keeps the thinking); the title is printed onto the picture the first time it exists. S6 Drawing (unless `own`, or the thumbnail is already drawn from these images and this instruction per its own stamp): instruction + "Do not write any words, letters, titles, logos or captions into the picture. Keep the <upper|middle|lower> part of the picture calm and uncluttered: a title will be printed across it afterwards."; frame = the video's aspect at long side 1280; base cropped, references raw; sd.cpp request {prompt, negative_prompt, width, height, seed −1, ref_images, auto_resize_ref_image, png} (steps/cfg left to the server); poll every second with "drawing (<status>)"; result → `thumbnail-plain.png`. S7 Print the marked texts then the title onto `thumbnail.png`; write `thumbnail.stamp`. S8 Missing title/instruction leave the previous value; the description is always replaced.

### F5.7 Page runs
- ↻ over the thumbnail: redraw from the images and instruction as they stand (clears "own"; always draws; "thumbnail drawn — ▶ renders the video").
- ↻ beside Title: rewrite title, instruction and description only ("title, instruction and description rewritten — ▶ renders the video").
- Set Thumbnail on an image: take it as it is, cropped; "thumbnail taken from <file> — the words are printed on it; ↻ draws over it".
- Words on the thumbnail: drag a box → dialog "Words on the thumbnail" (Remove / Cancel / Save); boxes snap to the picture's and each other's edges and middles; re-printing costs a decode, never a GPU run.
- ⤓ export: JPEG at the first of qualities 92, 85, 75, 60, 40 that fits 2 MiB (the last attempt is written even when it still does not; never rescaled); default name `<project>-thumbnail.jpg`, extension forced to `.jpg`; "nothing to export yet — draw a thumbnail, or use one of the images"; ">>> exported <path> (<size>)". ⤓ Save video: default name `<project>.<container>`, "saving <file>…" then "saved <file> — <size>"; "nothing to save yet — ▶ renders the video first".
- ⤓ Save video: a copy to a chosen path; ↻ Transcode: encode again without asking the model.

## 3. Data
`produce/clips/` (encodes, final.srt, final.<code>.srt, concat.txt), `produce/final.<ext>` + `.stamp` + sidecars + `.jpg` + `.html`, `produce/publish/` (`01-project-and-files.md` §5).

## 4. Parameters used
P.policy: minClipSeconds, gameVolume (0.22), subtitle break/row chars/max/hold/min, translateBatch, narration fitting (F4.3), loudness target (−14 LUFS, −1.5 dBTP, LRA 11), limiter (−1 dBFS), thumbnail long side (1280), title band, publish frames (3, max 8), briefMaxChars. Project: encoder settings. Engineering: input ordering, faststart flags, sd.cpp timeouts, poster quality, export ladder.

## 5. Rules
- The join is a stream copy: every clip must come out at one frame size and audio layout; -ss before -i; -t on the output for inserts, sounds, freezes and rated clips; adelay in whole milliseconds; input indices append-only; 0.5 s is the single clip floor; a dropped clip is always logged.
- Cues are built for every subtitle mode; sidecars are written whenever there is anything to say (a render with no narration and no speech writes none: "!!! nothing to put in a subtitle: no narration, and no speech in the clips") and stale ones are deleted first; never an empty cue; translations read back by number; gaps re-asked once then left in the original; the own language is never translated; webm carries no subtitle track.
- ▶ leaves an up-to-date video alone; the upload text is written once per project; `publish.json` is laid down before drawing; the thumbnail has its own stamp; ↻ over it always redraws; a chosen frame survives ▶; the title is seeded onto the picture once; re-printing words never costs a GPU run.
- The two halves touch no common file; every widget read happens before the goroutine; the `<video>` tag is rewritten even when the encode was skipped.

## 6. Details confirmed against the code (verification pass)
- **Clip planning refusals**: "clip N copies footage at T s that falls in no recording — skipped"; "clip N copies past the end of <base> — shortened to X s"; "clip N at T s falls in no recording — its sound has no picture, skipped"; "clip N runs past the end of <base> — shortened to X s"; an insert that keeps the sound under it but finds no recording, or one with no sound, "… — it plays silent". A clip takes its recording's first audio stream as its own sound only when that stream is among the source's selected `tracks`; otherwise it is heard through the lane mix. Narration on a card or held frame (no session span) is matched by exact bounds within 0.05 s. A line with no synthesis holds its cue to the next line or the clip's end. The planned 1× read head opens only where the sound would come adrift by ≥ 0.05 s; a card, a held frame or a clip on no recording closes the run. A moving camera forces a fixed frame grid even under VFR ("<clip>: the moving camera needs a fixed frame rate — this clip is N fps"). Each spoken line is time-stretched, resampled, panned across the output layout (a mono voice would otherwise land in one speaker) and delayed by whole milliseconds.
- **produce/clips/ also holds**: per-clip burn cue files `c%03d_<stamp>.srt`, one generated title document per text cue `…_t%02d.svg`, a written copy of any parameterised static card, a `.frames/` folder per baked animation, and the stream-copy `joined.<container>`; the folder is cleared at the start of every render.
- **Mux**: each subtitle track is its own input tagged with its ISO-639-2 code and name so players name them; a spoken language not in the list is tagged `und` and named by its upper-cased code; after a webm mux: "webm cannot carry an srt track — the subtitles are the files beside the video". A stored subtitle mode this build does not know reads as "none in the video" (an unknown answer must not letter somebody's picture); a stored resolution the list no longer offers falls back to the default. Legacy `produce` keys: `subs: "sidecar"` → "none"; `subs_from` dropped; absent `game_vol` = default while a stored 0 = silence; `bare` is the negation of the blurred-edges tick.
- **Translation**: a cue's line breaks go out as " / " and come back as breaks, then re-wrapped; a cue with no words is never counted missing nor re-asked; missing lines are named by number (">>> subtitles: <lang> came back missing line 7, 64, 92 -- asking again for N line(s)"; "!!! subtitles: <lang>: N line(s) left in the original (line 7, 92) -- the rest of the track is good"); answers are read back by number (tab, space, dot or colon after it), an unreadable line is skipped never shifted, the first answer per number wins; the cache holds the finished numbered track, only when complete (">>> subtitles: <lang> came from the cache -- the same lines were translated before"). Wrapping rebalances at the middle rather than dropping words; the track's last cue is extended to the readable minimum.
- **Frame boxes**: with no aspect the thumbnail is 16:9 at long side 1280; a frame box derivable from nothing is the chosen height (or 1080) at 16:9; both sides always even.
- **Publish**: legacy `base` index applied by moving that frame to the front; `title_off` read once; a one-line `frame: …` instruction is cleared on load (sent to the image model it drew nothing); an older `<project>/publish/` folder is honoured over `produce/publish/`. The deadlock breaker: when the text gate is closed but there is no picture, no images and no instruction, the text is asked for again ("    publish: no picture, no images and no instruction — asking for the upload text again"). A picked frame clears the instruction and the row holds that frame only ("    publish: the thumbnail is the frame at m:ss, as it is — no model, no GPU"; failure "    publish: <why> -- the thumbnail is drawn instead"). Prototype frame line: `frame: clip <n> +<seconds>` → that clip's start + offset, or a bare second / mm:ss; an unknown clip or a negative sum means no frame was named — never "take the first one"; a `THUMBNAIL: frame: …` line is a frame and the instruction is discarded; labelled lines peel in either order up to three, quotes stripped, a whole-reply fence removed first; a first description line under 40 chars ending in ":" is dropped. Candidate frames: the middles of three equal bands over the kept footage (never the first or last frame, never under an insert; the whole extracted set when the kept pool is too small; "    publish: no frames extracted either — drawing from the instruction alone"). Drawing: a missing base is an error ("the base image is gone: <path>"), a missing reference is skipped and logged; the request is logged with size, base, image count and crop ("    publish: WxH editing <base>, N image(s) sent, base cropped to P% of its width around cx,cy" / "…drawn from the instruction alone, no images"); "already drawn" needs both thumbnail files and a stamp match (frames by path and size@mtime, instruction, negative, crop centre, aspect, own); the chosen-picture branch prints the words before the text-only gate, so ↻ Suggest that picks a frame still gets its title; printing failure keeps the plain picture. The title band is a box only while the picture carries words; its ✎ edits the picture's line; Remove keeps it off for good; the YouTube title never re-prints the picture. Text boxes: only the ✎ chip opens the dialog ("Printed to fill the box you marked — a longer line comes out smaller, and Enter starts a new line."); a drag under 8 px marks nothing; a box saved empty is not created / is removed; with nothing to print the plain bytes are copied through untouched.
- **<video> tag**: tracks read off disk (the tag is rewritten even when the encode was skipped), own language first, the rest by name, `default` on the first only; notes "no browser plays Matroska — render to mp4 or webm for a page" / "Firefox plays no h265 at all, and the others only where the machine decodes it in hardware — h264 is the one that plays everywhere"; a poster that cannot be written is logged and the tag written without one.
- **Stamp**: a stamp that cannot be computed or written never matches ("    produce: could not write the render stamp (…) — the next ▶ will encode again"); never fails the run.
